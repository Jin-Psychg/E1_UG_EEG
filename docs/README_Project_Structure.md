# UG ERP Project — Project Structure & Reproducibility Guide

This document describes the directory layout and analysis workflow for
the Ultimatum Game (UG) ERP study covering Experiment 1 (E1: sequential
face-then-offer) and Experiment 2 (E2: simultaneous face+offer). It is
intended for collaborators and external researchers reproducing or
extending the analyses.

The project root is whatever directory contains `UG_ERP_Project.Rproj`;
on the development machine this resolves to `C:/Code/UG_ERP_Project/`.
R scripts find this root automatically via the `here` package; most
Python scripts auto-detect it. Two scripts rely on hardcoded absolute
paths and require one-line edits when the project moves machines; see
section 5 for which lines.

### Note on the HDDM script

`hDDMdetails/Final_vazt-Unfair_Grouplevel_InformativePr_E1.ipynb` and its
`_E2.ipynb` counterpart run Hierarchical Drift Diffusion Modeling on the
unfair-trial RT/choice data — one notebook per experiment, same 6-step
pipeline. Model: 4-parameter DDM (v, a, t, z; no across-trial variability
sv/st/sz) fit with HDDMRegressor, every parameter regressed on emotion via
group-level treatment contrasts (`group_only_regressors=True`) under
informative priors (Wiecki, Sofer & Frank, 2013). Trials: unfair only;
Accept=1 -> upper boundary (1), Reject=2 -> lower boundary (0).
The canonical HDDM analysis is maintained in a parallel project tree
(separate environment and dependencies); the notebooks under `hDDMdetails/`
are reference copies only — consult that parallel project for the canonical
version and environment specification.

### Naming conventions for raw input

- Participant ID is extracted from each filename via the regex `\d+`
  (first contiguous run of digits). `Vp0001.set`, `subject_1_eeg.set`,
  and `1_data.set` all resolve to ID 1. Avoid filenames where the first
  numeric run is not the participant ID (e.g., `pilot_S01_v3` collides
  with any other file whose first digit run is also 1).
- EEG and log files are paired by ID. `Vp0001.set` in
  `raw_all_cropped_E2/` is matched to `Vp0001.txt` in `csv_all_E2/`.
- BrainVision recordings consist of three files (`.vhdr`, `.eeg`,
  `.vmrk`) sharing the same base name. All three must be present in the
  same directory; the `.vhdr` references the others by relative path.

### The integrated trait/rating spreadsheet

`SVO_PID5BF_PostRating_<EXP>.xlsx` is the input for the Stage 2
individual-difference analysis. It is NOT produced by the preprocessing
script and must be prepared by hand from:

- SVO (Social Value Orientation) raw scores: `SVO_angle`, `SVO_type`
- PID-5-BF dimensions: `Negative_Affectivity`, `Detachment`,
  `Antagonism`, `Disinhibition`, `Anankastia`, `Psychoticism`
- Post-experiment rating items: `Rating_1`, `Rating_2`, `Rating_3`

The participant ID column should be the first column (any name is
accepted; the loader treats column 1 as the ID). Missing trait columns
are silently skipped by `load_covariates()` in the statistical scripts.

### Why three EEG sub-trees?

`results/EEG/` contains three independent trees because they are
written by different scripts for different purposes:

1. `E*_TwoStage_Bates_Alday/` and `E*_TwoStage_Bates_Traditional/` are
   produced by the R statistical scripts (sections 4.3, 4.4). They
   contain numerical results: ANOVA tables, post-hocs, model
   summaries, R-squared, BLUPs.
2. `Results_<comp>_<EXP>/Session_<ts>/` is produced by the Python EEG
   visualization script (section 4.8). It contains figures and the
   intermediate CSV files that the R topographic plotting script
   (section 4.6) consumes downstream.

The two trees serve different stages of the manuscript: numerical
inference (statistical scripts) vs. publication figures (visualization
scripts). They reference each other only at the section 4.8 to 4.6
handoff (Python EEG viz produces what the R topo script reads).

## 4. Scripts

For each script: input source, output location, path-handling style,
and any caveats.

### 4.1 Pipline_UG_OfferPhase.Rmd

EEG preprocessing master script. Wraps `hu-neuro-pipeline` (vendored
MNE-Python module) with R-side configuration and condition-list
generation.

- Toggle `experiment_version <- "E1"` or `"E2"` (line 33).
- Toggle `use_baseline_correction <- TRUE` for Method_Standard,
  `FALSE` for Method_Regression. Run twice with opposite settings to
  produce both trees.
- Inclusion criteria: `reaction > 0` AND `RT >= 300` AND `RT <= 3000` ms.
- Reads: `data/00_Raw_Input/{raw_all_cropped,csv_all}_<EXP>/`
- Writes: `data/01_Preprocessing_Logs_<EXP>/`,
  `data/02_Pipeline_Output_<EXP>/{Method_Standard,Method_Regression,Covariates,Baseline_Raw}/`
- Path style: `here()`. Position-independent.

### 4.2 Sta_Behaviour_E1_E2_Integrative.Rmd

Behavioral GLMM + LMM analyses. Three models per experiment:
GLMM_Rejection (rejection probability), LMM_RT_main (all-trials RT),
LMM_RT_unfair (unfair-trials RT, parallel to HDDM).

- Runs all three stages in one render via `stages_to_run <- c("E1", "E2", "Integrative")`
  (no per-render `experiment_version` toggle); the Integrative stage pools E1+E2 with
  Experiment as a between-subjects factor for a 3-way interaction.
- Reads: `data/02_Pipeline_Output_<EXP>/Method_Regression/Stimulus_Locked/trials.csv`
  (also reads from Method_Standard if Method_Regression is unavailable).
- Reads: `data/02_Pipeline_Output_<EXP>/Covariates/SVO_PID5BF_PostRating_<EXP>.xlsx`
- Writes: `results/Behavior/<EXP>_TwoStage_Bates/`
- Path style: `here()`. Position-independent.

### 4.3 Sta_EEG_OfferPhase_RefAlday.Rmd

PRIMARY EEG single-trial LMM analysis using the Alday (2019)
baseline-as-covariate framework. Two-stage: Stage 1 fixed-effect
inference per component; Stage 2 BLUP-based individual-difference
correlations.

- Toggle `experiment_version`.
- Reads: `data/02_Pipeline_Output_<EXP>/Method_Regression/Stimulus_Locked/trials.csv`
  (must contain Baseline_<comp> columns).
- Reads: `data/02_Pipeline_Output_<EXP>/Covariates/SVO_PID5BF_PostRating_<EXP>.xlsx`
- Writes: `results/EEG/<EXP>_TwoStage_Bates_Alday/`
- Path style: `here()`. Position-independent.

### 4.4 Sta_EEG_OfferPhase_RefTraditional.Rmd

SENSITIVITY EEG single-trial LMM analysis using traditional baseline
subtraction (subtraction performed upstream in preprocessing).
Mirrors section 4.3 but without the baseline covariate. Stage 2 is
deliberately disabled; see `STAGE2_DISABLED_README.md` in the output
directory for rationale.

- Toggle `experiment_version`.
- Reads: `data/02_Pipeline_Output_<EXP>/Method_Standard/Stimulus_Locked/trials.csv`
- Writes: `results/EEG/<EXP>_TwoStage_Bates_Traditional/`
- Path style: `here()`. Position-independent.

### 4.5 Visualization_Behavior_E1E2Integrative.py

Behavioral visualization script. Reads the statistical output from
section 4.2 and renders publication-ready figures (forest plots,
posthoc panels, raw-data scatter overlays) into the same directory.

- CLI flags: `--e1`, `--e2`, `--integrative`, `--debug`.
- Reads: `results/Behavior/<EXP>_TwoStage_Bates/` (statistical output)
  and `data/02_Pipeline_Output_<EXP>/Method_Regression/Stimulus_Locked/trials.csv`
  (raw scatter data).
- Writes: figures into `results/Behavior/<EXP>_TwoStage_Bates/`.
- Path style: auto-detect project root by searching up to 6 parents
  for a directory containing `results/` or `data/`. Position-independent.
- Backward-compat: also recognizes legacy directory names
  (`Behavioral` vs `Behavior`, `_Pub_Output_Final` vs `_TwoStage_Bates`).

### 4.6 Topo_Master_StiLocked_RefAlday.Rmd

Downstream of section 4.8. Renders ERP topographic maps for each
component using both Regression-corrected and Standard-baseline data

- Toggle `experiment_id <- "E1"` or `"E2"` (line 28).

- Writes: `results/EEG/Results_<comp>_<EXP>/Session_<latest>/<method>/topoplots_R_<comp>/`

Three helper scripts, not part of the numbered main flow:

## 5. Reproducibility caveat: hardcoded paths

One active script contains a hardcoded absolute path that must be edited when
the project is moved or copied to a new machine (a second, archived, is listed
for completeness):

| Script | Line | Current value | Edit to |
|--------|------|---------------|---------|
| `Topo_Master_StiLocked_RefAlday.Rmd` | 31 | `"C:/Code/UG_ERP_Project/results/EEG"` | path to your project's `results/EEG` |
| `Visualization_Cluster_Permutation.Rmd` (archived) | 230 | `"C:/Code/UG_ERP_Project"` | archived in `Old_Scripts/`, not run — no edit needed |

All other scripts (Pipline, Sta_*, Visualization_Behavior_E1E2Integrative.py,
Visualization_EEG_StiLocked_RefAlday.py) auto-detect their working directory
and require no edits when relocating.

## 6. Reproducibility checklist

To reproduce the full analysis from raw data:

1. Place raw EEG and behavioral logs in `data/00_Raw_Input/<...>_<EXP>/`
   (see section 2 for naming conventions). Verify pairing:

   ```r
   library(here); library(stringr)
   exp <- "E2"
   eeg_ids <- as.integer(str_extract(
     basename(list.files(here("data", "00_Raw_Input", paste0("raw_all_cropped_", exp)),
                         pattern = "\\.(set|vhdr)$", ignore.case = TRUE)), "\\d+"))
   log_ids <- as.integer(str_extract(
     basename(list.files(here("data", "00_Raw_Input", paste0("csv_all_", exp)),
                         pattern = "\\.txt$")), "\\d+"))
   identical(sort(eeg_ids), sort(log_ids))   # must be TRUE
   ```

2. Place the integrated trait/rating spreadsheet at
   `data/02_Pipeline_Output_<EXP>/Covariates/SVO_PID5BF_PostRating_<EXP>.xlsx`.
   This requires `02_Pipeline_Output_<EXP>/` to exist; create the empty
   directory by hand or run preprocessing once first.

3. If reproducing on a new machine, edit the two hardcoded paths
   listed in section 5.

4. Run preprocessing (4.1) twice with opposite `use_baseline_correction`
   settings to populate both `Method_Standard/` and `Method_Regression/`.

5. Run statistical scripts (4.2, 4.3, 4.4) for each experiment. Each
   writes a `REPRODUCIBILITY.txt` recording R version, package
   versions, model formulas, inferential method, and Bates 5-step
   diagnostics. A `Methods_paragraph_<EXP>.md` keeps the manuscript
   Methods text in sync with the actual code path.

6. Run visualization scripts (4.5, 4.7, 4.8). Run the topographic
   script (4.6) AFTER the EEG visualization script (4.8) has populated
   `Results_<comp>_<EXP>/Session_<>/`.

## 7. Backup strategy

| Path | Backup priority | Reason |
|------|-----------------|--------|
| `data/00_Raw_Input/` | Critical, off-site | Irrecoverable; comes from the experiment |
| `SVO_PID5BF_PostRating_<EXP>.xlsx` | Critical, off-site | Manual integration; loss requires re-entry |
| Analysis scripts (`*.Rmd`, `*.py`) | Critical, version-controlled | Encode the analysis pipeline |
| `data/01_*`, `data/02_*` | Optional | Regenerable from raw data + scripts |
| `results/` | Optional | Regenerable; commit key outputs to git for record |

A common operating-system safeguard is to make `data/00_Raw_Input/`
read-only at the filesystem level (e.g., `chmod -R a-w` on Unix; the
"Read-only" attribute on Windows folders). Pipeline scripts only read
from this directory, so the read-only flag does not interfere.

## 8. Software environment

R packages are managed via `renv` (see `renv.lock`). Run
`renv::restore()` on a fresh checkout to install the pinned versions.
Each `REPRODUCIBILITY.txt` produced by statistical scripts records
the actual versions used during the run.

Python dependencies: `hu-neuro-pipeline` is vendored under
`python_modules/`. The scripts resolve it via `reticulate` against the
conda environment `r-reticulate` (configured in
`Pipline_UG_OfferPhase.Rmd`, section "Python Environment Initialization").
The two Python visualization scripts use standalone Python (not

## 10. Face phase (E1 only) — separate supplementary module

The face-locked analysis (how the proposer's facial emotion is processed at
*face onset*, before the offer appears) exists only for E1 (sequential design;
in E2 face and offer are simultaneous, so there is no separable face phase). It
is kept as a **self-contained, separately stored module** because it is expected
to appear as supplementary material.

**Scripts — all in one folder `FacePhase_E1/` (project root):**

```
FacePhase_E1/
├── Pipline_UG_FacePhase_E1.Rmd          face-locked EEG preprocessing
├── Sta_EEG_FacePhase_E1.Rmd             face-locked single-trial LMM (stats)
├── Visualization_EEG_FaceLocked_E1.py   waveforms + emotion-minus-Neutral diff waves + topo CSVs
└── Topo_Master_FaceLocked_E1.Rmd        topographic maps (downstream of the .py)
```

Paths are position-independent: the `.Rmd` use `here()` and the `.py` auto-detects
the project root, so the scripts work from this subfolder without edits.

**Config (shared SSOT, stays in `config/`):**
`config/erp_components_face_E1.csv` — classic literature windows/ROIs for the
face components **P1, N170, EPN, LPP_face** (separate from the offer
`config/erp_components.csv`, so the offer pipeline is untouched).

**Pipeline data (regenerable; stays in the `data/` tree, parallel to the offer phase):**

### Design specifics (differ from the offer phase)

- **Single factor `emotion`** (5 levels: neu/aff/dis/dom/enj), NOT
  `emotion * offer_type`: at face onset the offer is not yet shown, so fairness
  is not a factor and no 7:3 filler exclusion applies. Trial inclusion otherwise
  matches the offer/behavioral analyses (`reaction != 0`, RT in [300, 3000] ms).
- **Method toggle** `use_baseline_correction` in both `.Rmd` (FALSE = Alday primary
  / `Method_Regression`; TRUE = traditional sensitivity / `Method_Standard`),
  mirroring the offer pipeline. The Bates random-structure engine is reused
  verbatim; only the fixed-effect structure is reduced to one factor.
- **Triggers** `c(101:115, 201:215)` (E1 face-onset codes; see `.claude/CLAUDE.md`).
- **Timing**: face 1500 ms -> fixation 500 ms -> offer (>= 2000 ms post face onset),
  so the LPP_face 500-800 ms window is clear of offer-evoked activity.
- **Stage 2 covariate roles** (same policy as the offer Alday script):
  SVO_angle & Negative_Affectivity = moderators; Rating_1/2/3 = nuisance
  covariates (separate main-effect control model); PID-5-BF = exploratory BLUP.
